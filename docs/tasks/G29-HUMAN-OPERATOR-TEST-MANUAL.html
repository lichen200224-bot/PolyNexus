Human Operator Test Manual
WP-20 Level 3A External Web Verification

給已授權 Human operator 的 ChatGPT、Claude、Gemini Web 操作、failure-path 測試、證據整理與驗收手冊。

Version: 2026-09-03 Owner: authorized Human operator Status: G29 handoff / execute in G30 WP-20 allocation: +5
重要狀態：本手冊是 G29 準備、G30 執行用的操作材料，不代表 G29 或 G30 已通過。G30 只有在三個必要 vendor 都有完整 sanitized report、failure/fallback evidence、無 security/egress BLOCKER 或 MAJOR，且完成獨立 review 與 Human acceptance 後，才可將 WP-20 從 0/5 提升為 5/5。

1. 目的、角色與不可違反的界線

Human operator 責任

  • 使用指定的非 production 測試帳號，並確保帳號 owner 在場。
  • 每次真實送出前，親自確認 exact payload 與 target conversation。
  • 操作 live route 或明確標籤的 CONTROLLED_FIXTURE。
  • 只回傳 sanitized report 與遮罩後的 screenshot/trace reference。

Codex / 系統邊界

  • 不得取得、要求、保存或輸出 password、cookie、token、recovery code。
  • 不得保存 private conversation、account identifier 或 raw page data。
  • 不得自動登入、自動送出或繞過帳號 controls。
  • AI opinion 不得被寫成 verified evidence 或 vendor certification。

停止條件

  • 沒有 safe test account、owner consent 或 supported browser。
  • 頁面要求不在批准範圍的資料、權限或登入操作。
  • 無法遮罩 screenshot/trace，或看到 secret/account data。
  • 任何不確定的 send target、payload 或 external request。

2. 測試前置檢核

不要測試：production account、真實 project context、customer data、private conversation、帳號設定變更、強制 logout、credential export、DevTools network body/header 或 browser storage。

3. 唯一批准的安全測試 payload

除非帳號 owner 另行批准等價的非敏感 payload，請逐字使用下列內容。不要加入專案內容或個人資料。

PolyNexus G29 compatibility check. Reply with the single word CHECKED.
Do not include personal, confidential, production, or account data.

成功結果只需記錄 bounded summary，例如 CHECKED received。不得複製或回傳整個 raw response。

4. 每家 vendor 的 Level 3A 主流程

對 ChatGPT、Claude、Gemini 各執行一次。每家使用獨立 tab/session，並各填一份 report。成功主流程是：Launch → Detect → Fill → Human inspect/confirm → Send → Capture → Normalize → Cleanup。

1
Record context記錄 vendor、browser version、extension version、UTC time、route label。只寫版本與類型，不寫帳號識別值。
2
Launch從 companion 開啟該 vendor 的核准 origin。檢查 tab 是否是正確 vendor route；不開啟不明 redirect 或其他 tab。
3
Detect執行 composer/readiness check。只記錄 PASS、FAIL 或 bounded blocker；不要貼 raw DOM、selector value 或頁面 dump。
4
Fill只填入上方安全 payload。停止並目視檢查畫面：文字完全正確、沒有額外內容、target conversation 正確。
5
Human-confirmed Send帳號 owner 必須明確確認 exact payload 與 target。只有確認後才可按 send；report 才能寫 HUMAN_CONFIRMED_SEND=YES。
6
Capture只記錄 bounded result，例如 CHECKED received。不要保存 raw page、raw response、request body 或 headers。
7
Normalize透過 companion 產生 bounded AI_OPINION summary。這只是外部模型意見，不是 verified evidence、PASS certification 或安全判定。
8
Cleanup關閉 test tab；若使用 temporary profile，清除 profile、downloads、certificates 與 session exports；確認只留下 sanitized artifacts。

每個主流程 phase 的檢核標準

Phase可寫 PASS 的條件不可寫成 PASS 的情況應記錄的 bounded evidence

Detectcomposer/readiness 可被安全辨識。selector mismatch、頁面狀態不確定、需改 vendor page。PASS/FAIL 與 bounded blocker。

6. Failure-path 詳細操作與檢核

Expired login

  1. 使用預先準備的 expired/non-authenticated safe state，或明確標示 unavailable。
  2. 只檢查 bounded readiness result。
  3. 不要 force logout、讀 session、取 cookie 或 screenshot storage。

Pass evidence： LOGIN_STATUS=EXPIRED 或 UNAVAILABLE，無 send。

Selector mismatch

  1. 使用 controlled page state，或記錄 live page 沒有 expected composer/button。
  2. 不要修改 vendor page、注入繞過程式或改 selector 來製造 PASS。
  3. 切到 manual/clipboard fallback。

Pass evidence： driver failure isolated + fallback recorded。

Cancelled send

  1. Fill 後讓 confirmation 出現。
  2. 確認 owner 選 cancel/decline，或不作確認。
  3. 檢查沒有 external request/send。

Pass evidence： HUMAN_CONFIRMED_SEND=NO，bounded confirmation-required outcome。

Timeout

  1. 使用事先約定的 local timeout。
  2. 到時停止等待，不重試、不重複提交。
  3. 確認 cleanup 與無 unintended send。

Pass evidence： bounded timeout/degraded result + cleanup。

Capture failure

  1. 不要複製 raw response。
  2. 改用已遮罩的 manual/clipboard summary。
  3. 記錄 fallback 是否成功匯入。

Pass evidence： CAPTURE_RESULT=FALLBACK，raw data 未保存。

Normalization failure

  1. 記錄 bounded fallback/error。
  2. 不猜測結果、不補寫 AI opinion。
  3. 保留 no-additional-send。

Pass evidence： NORMALIZE_RESULT=FALLBACK 或 FAIL，沒有 fabricated claim。

7. Screenshot、trace、clipboard 與 cleanup 檢核

只保留最小必要證據

分享前最後一次掃描：若發現任何 secret、email、account identifier、raw response、private text、request body/header 或未遮罩 screenshot，先移除並在 report 只記錄「已移除的類別」，不要把原值貼回 Codex。

10. Computer / browser 工具說明

若 Codex session 有可用的 Browser/Chrome companion，Human operator 可在確認安全 payload 與 target 後使用它協助 Launch/Detect/Fill/Capture；send 仍必須由 Human 明確確認。工具不得代替登入控制、帳號 owner consent 或安全檢查。

目前 G30 session 的狀態：已嘗試 computer/browser probe，但沒有可用的 browser/page/computer binding，Playwright 與 local Chrome CDP 也不可用。因此本手冊應由授權 Human 直接在 supported browser 執行；若要讓 Codex 協助，請先啟用/連接 Codex Browser 或 Chrome companion，再重新開始同一套流程。
  1. 啟用 Codex Browser/Chrome companion，確認只連接指定 browser profile。
  2. 由 Human 在畫面上確認 vendor route、safe payload 與 target。
  3. 逐家執行本手冊第 4–6 節與第 5 節矩陣。
  4. 送出前再次由 owner 明確確認；不確認就取消，不得代送。
  5. 只回傳第 8 節的 sanitized reports 與遮罩後 refs。

12.4 Windows 安裝

需求：Python 3.12+、Node.js 22.12+、npm 與 Git。從 clone 的 repository root 執行既有 setup script：

python --version
node --version
npm --version
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup_dev.ps1

此 script 會建立 repository-local .venv、安裝 services/core[dev]，並安裝 apps/web dependencies。安裝產物（.venv、node_modules、build output）只留在該 isolated clone，不要加入 stage。

若需要完全依照 lockfile 的 Web 安裝，可在 apps/web 使用：

Set-Location .\apps\web
npm ci
Set-Location ..\..

網路、registry、權限或 Python launcher 失敗時，保留 exact command 與 actual exit code，標成 environment blocker；不要以歷史 PASS 取代本機結果。
