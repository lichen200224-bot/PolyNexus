# WP-19 — WebSurface and authenticated loopback boundary

## Scope

Internal deterministic acceptance of the Chrome MV3 thin companion boundary,
vendor-driver isolation, user-confirmed send, bounded normalization, manual /
clipboard fallback, and authenticated `127.0.0.1` Core access.

## Acceptance criteria

- Vendor selectors remain in site drivers; Core remains vendor-neutral.
- The assisted flow launches, health-checks, fills, pauses for explicit user
  confirmation, sends only when confirmed, captures, and normalizes as
  `AI_OPINION`.
- Driver, scripting, empty-output, invalid-response, and clipboard failures
  degrade to a bounded manual/clipboard fallback without crashing Core.
- Loopback requests require `127.0.0.1`, an explicitly configured token, and
  bounded GET/POST paths/bodies/responses; redirects and credential-bearing
  URLs fail closed.
- Tokens remain session-memory-only and never enter URLs, storage, logs,
  evidence, or normalized output.
