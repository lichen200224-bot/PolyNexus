## Goal

Provide a deterministic, Core-only Doctor MVP that reports runtime identity,
current health/readiness, adapter-declared version/capabilities, truthful
maturity, separate conformance evidence, UTC timestamp, and fixed sanitized
error categories. The report is read-only and is not an execution routing or
production runtime detection surface.

## Architecture decision

The accepted decision is recorded in
`docs/31_ADR_012_RUNTIME_DOCTOR_REPORTING.md` and `docs/10_DECISION_LOG.md`.
The Doctor owns a fixed ordered tuple of specs and registers those specs into a
fresh private `RuntimeRegistry` for each collection. The existing default
registry remains reference-only. The frozen `RuntimeAdapter` method set and
`RuntimeCapabilities` contract are not modified.

Default identity/maturity policy:

## Implemented behavior

- Immutable ordered Doctor inventory and dedicated composition root.
- Fresh registry per report; no implicit reference fallback or default-registry
  mutation.
- Current async health/readiness probes with bounded timeout and cancellation.
- Adapter declaration sources for capabilities/version; separate conformance
  evidence fields.
- `COMPLETE` can contain a valid unhealthy `False` probe; probe errors produce
  `PARTIAL`; malformed/duplicate/unhashable inventory produces `FAILED` with no entries.
- Factory failure yields a sanitized unavailable row (all sources = UNAVAILABLE) while other rows continue.
- Raw exception values, text, args, cause, context, and tracebacks are never
  included in report output.
- Public capability reports are reconstructed from validated enum/bool fields;
  malformed capability objects and credential/claim-shaped evidence metadata fail
  closed without echoing raw values.
- Doctor invokes only health/readiness/capabilities/version_info; lifecycle
  methods are out of scope.
